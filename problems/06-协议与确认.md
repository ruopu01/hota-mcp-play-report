# 06 · 协议与确认：不是 bug，但必须会读

这一篇是"行为设计"层面的东西。它们**不是缺陷**，但如果不理解，
你会像我第一局那样把 42 次调用浪费在 `STALE_REVISION` 上。

---

## 7 · `uncertain` 的含义

```json
{"status": "uncertain",
 "message": "Dispatch started; do not repeat using a new ID"}
```

**它= "我把动作发出去了，但在超时窗口里没看到世界变化"。**

三种真实结局：

| 实际 | 表现 |
| --- | --- |
| 动作生效了，只是变化没被读到 | 下次 observe 会发现状态确实变了 |
| 动作还在路上 | 过一会儿再看，变了 |
| 动作丢了 | 一直没变 |

**正确做法**：`observe` 复核。

- 变了 → 当作成功；
- 没变 → 用**同一个 `operationId`** 重试（幂等保护会让它安全重放）；
- **绝对不要换新 id**：那等于"再点一次"，在建造/移动上就是砰第二下。

我踩过的坑：`building:buy` 返回 `uncertain`，我以为失败、换了新 id 再点，
结果第一个其实也生效了 —— 好在钱不够，第二下被游戏拒了。

## 8 · 随机图的"城镇"候选被计时器污染

在随机图的高级选项里问"红色可选哪些城"：

```text
act setup:красный:город:Замок
→ «Замок» не предлагается в столбце «город» у цвета «красный».
   Игра предлагает: 00:00 + 00:00 + 00:00
```

**"游戏提供的候选是 00:00 / 00:00 / 00:00"** —— 这是那个界面里
"Player Turn Duration: Classic"（元素 `{Timer:}` + `Classic`）的文本框内容，
被当成了城市的候选列表。

后果：只用名字选城会失败。绕法是 `setup:красный:город:вперёд` / `:назад` 轮转
（截图显示默认就是 Castle，其实不用动）。

## 9 · `Топтание`：它会观察你的"原地打转"

连续 6 次 `observe` 而世界没有任何变化时，`brief` 里会出现：

```
Топтание: 6 наблюдений подряд без единого изменения
```

这是**给你（agent）的提示**，不是错误。但很容易被误读成"卡住了/坏了"，
然后做出错误决策（比如以为动作失败而重试）。

我的处理：把它当"我在空转"的信号 → 检查移动力是否耗尽、是否该结束回合。

## 10 · 能力边界（`game_status.capabilities`）

```json
"capabilities": ["observe_own_hero", "observe_adventure_ui", "move_to_target",
                 "town_construction", "combat_actions", "save_game", "launcher_tab", ...],
"unavailable":  ["full_map_coverage", "hotseat", "lan", "full_scenario_setup",
                 "cost_measurement"]
```

- `hotseat` / `lan`：**明说没做**。`observe` 的文档里写着 "so a hotseat …"，
  但能力表里是 unavailable —— 以能力表为准；
- `start_game`：只在 HD Launcher 托管（`--launch`）时可用，否则
  `Server must be hosted by HD Launcher to start the game`；
- `full_scenario_setup`：随机图模板/尺寸只支持一部分，这就是问题 8 的土壤。

**教训**：动手前先读 `capabilities`，能省掉一半"为什么这个动作没有"的困惑。

## 附：战斗里的一条硬规则

`combat:wait`（等待）**每轮只能用一次**，第二次：

```
[UNKNOWN_CONTROL] Action unavailable
```

同理 `combat:defend` 之后该单位就不能再行动。这类"回合内状态"只能靠
`stacks[].acted` / `stacks[].defending` 自己记账 —— 适配器不会替你记。
