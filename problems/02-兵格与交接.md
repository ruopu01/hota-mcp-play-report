# 02 · 兵格与交接：最常用的一条链路，全断了

> **严重度：🔴 高**。英雄招的兵、城镇驻军里的兵，**没有任何语义动作能挪动**。
> 影响："招兵 → 送给主英雄 → 上前线"这条最基本的运营循环。

---

## 现象：一组动作全部报"找不到兵格"

在城镇界面（`town` 屏），下面这些动作**无一例外**失败：

| 动作 | 原始报错 |
| --- | --- |
| `army:give:Pikeman` | `Клетка 0 нижнего ряда не найдена на экране города` |
| `army:open:h0` / `h1` / `h2` | `Клетка 1 нижнего ряда не найдена на экране города` |
| `army:split-give:Griffin` | `Клетка 2 нижнего ряда не найдена на экране города` |
| `army:take:Mammoth` | `Клетка 3 верхнего ряда не найдена на экране города` |
| `town:lead`（合兵） | `Town garrison row control not found in the town dialog` |
| `hero:out`（放英雄出城） | 同上 |

翻译：**"在城镇界面找不到上/下排第 N 格"**。

值得注意的是，`army:give` 的动作标签**会正确预告合并结果**（例如 `16+13=29`），
说明"计算"是对的，只是"点到那个格子"的坐标查找失败了 —— 也就是说
**兵格控件在这个 UI 变体里没有被识别成可点击元素**。

城镇屏的 `elements` 里确实只有：

```
ui:59 "16"   ui:60 "4"   ui:61 "5"      ← 兵力数字（纯文本）
ui:73 iam014.def   ui:74 iam015.def     ← 左侧按钮
ui:75/76 tsbtns.def                     ← 底部按钮
ui:78 "Armitage"(城镇名)  ui:87 townhrtd.def
```

**没有任何 `ui:` key 对应兵格本身**。所以这是"观察层没暴露 + 动作层硬编码查找"的双重失配。

---

## 绕法（三条，全部实测有效）

### 1) 用 `hero:switch` 代替 `hero:out` / `town:lead`

```text
town:close
  → 在城镇屏按 hero:switch（驻军英雄 ↔ 来访英雄互换，双方部队自动合并）
  → 再 town:close
  → 英雄已经站在地图上了（(8,12) 城门口）
```

`hero:switch` 是**唯一**能改变"谁在城内"的可行动作，而且它顺带完成了合兵。

### 2) 用 `town:exchange` 的 `exchange:army:left|right` 运兵

把两个英雄凑到一起（一个在城里当"驻军英雄"、一个站到城门口），`town:exchange` 打开交换屏：

```text
exchange:army:right   # 把所有兵给右边英雄
→ Rion: было [Pikeman x13, Griffin x5] → [Pikeman x1]
  Adelaide: → [Pikeman x28, Archer x4, Griffin x10]
```

- **游戏不允许清空最后一格**，所以转移后原英雄必留 1 个；
- 方向的语义是"给谁"，`left/right` 由谁在左谁在右决定，**读动作文字里的 before/after 更可靠**；
- 反方向有 `exchange:take:*`；
- `exchange:close:left|right` 会返回 `uncertain` 且**不关窗**，只能发 Esc。

### 3) 升级兵种：像素双击 + 语义动作

```text
在城镇界面双击兵格像素（Archer 格中心 ≈ (586,530)，间隔 120 ms）
  → 打开 creature_card 屏
  → 语义动作变成：army:upgrade / army:dismiss / army:close / split:cancel
army:upgrade
  → message 屏 "650"（13 × 50 金）
  → message:confirm
  → Archer x13 → Marksman x13
```

这条组合**稳定可复现**，是我第二局升出 32 个神射手的唯一办法。

---

## 为什么算缺陷而不是"设计如此"

- 动作**存在**、标签写得明明白白（`army:give:Pikeman`、`16+13=29`），说明作者**意图支持**；
- 报错是 `ActionRefused`（适配器自己抛的），而不是游戏拒绝；
- `hero:out` / `town:lead` 同时失效，说明不是单个动作的问题，而是**这一屏的控件定位整体没适配**。

作者大概率是在某个特定分辨率/HD Mod 配置下开发并验证的；我这个 1180×664 的布局里，
兵格矩形没被识别出来。
