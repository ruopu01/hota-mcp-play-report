# 01 · 读屏崩溃：一次 `OverflowException` 让整局不可观测

> **严重度：🔴 致命**。这不是"某个工具不好用"，而是**所有观察入口同时失效**，
> 唯一的出路是杀进程重来（或者读档回到崩溃前）。

---

## 现象

随机图 + "Tournament Rules" 弹窗点确认之后：

```text
act popup:подтвердить
→ Arithmetic operation resulted in an overflow.
```

从这一刻起，**每一个**读屏工具都返回同一句话，持续 polling 也不会恢复：

| 工具 | 返回 |
| --- | --- |
| `observe` | `Arithmetic operation resulted in an overflow.` |
| `nearby_targets` | 同上 |
| `game_status` | 同上 |
| `debug_snapshot` | 同上 |
| `debug_capture` | 同上 |
| `minimap_capture` | 同上 |

而 `game_status` 的"底层探针"是好的 —— 但它也走同一条读屏路径，所以同样炸。
**唯一的旁证**是我用 Windows 截图随便拍了一张：游戏确实已经进了冒险地图，窗口标题、
HUD 一切正常。也就是说：**游戏没问题，是适配器读它的时候算溢出了。**

---

## 复现步骤

```
1. 新游戏 → 单人 → 随机地图（36×36 或 72×72 都行）
2. 进"Show Advanced Options"，随便设一下玩家/城
3. Begin → 弹出 "Tournament Rules" 复选框
4. popup:подтвердить
→ overflow，此后所有读屏永久失败
```

我用同样的流程、**不走随机图**（默认固定图 Air Supremacy）时：

```
scenario:start → completed → message 屏（开场信）→ 一切正常
```

所以触发条件是 **"随机图 + 开局弹窗"这个组合**，不是"随机图"本身。

---

## 我的判断

能确定的部分：

- `ToolErrors.Filter` 只把 `ActionRefused` 转成 `[CODE] …`，**其他异常原样抛**，
  所以模型看到的是裸的 .NET 异常文本，没有任何上下文（哪个字段、哪个偏移）；
- 溢出发生在**读状态**这一层，而不是某个工具的解析逻辑 —— 因为 `debug_snapshot`
  （最原始的接口）也炸；
- 这类"读 32 位结构时 `int` 运算越界"的典型来源是：`address + length` 相加溢出、
  或者把某个 `uint` 当 `int` 做乘法（尺寸/评分/评分表之类）。

不能确定的部分：到底是哪个字段。要定位得改源码打日志，而我**没有编译环境**
（这台机器上没有 .NET SDK），所以只能记录现象。

---

## 绕法

1. **回到固定图**：默认地图（Air Supremacy 等）走同样的开局流程不会触发；
2. **不要在随机图的 Tournament Rules 弹窗上确认** —— 但这一步不确认就进不了游戏，
   所以实际上等于"别用随机图"；
3. 已经卡死时：`Stop-Process h3hota` 重开，或读 `AUTOSAVE.GM1`。

---

## 为什么归为"致命"

因为它**没有任何降级路径**：

- 不会自动重连（`game_status` 也炸，连"我坏了"都说不出来）；
- 没有 `force_observe` / `raw_read` 之类的低层接口；
- 错误信息里没有可操作的线索（不像 `[STALE_REVISION]` 那样告诉你怎么办）。

对 agent 来说，这等于"眼睛被人蒙住，还没人告诉你被蒙住了"。
