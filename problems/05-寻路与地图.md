# 05 · 寻路与地图：明明能走，它说走不了

> **严重度：🟠 中**。一部分是游戏寻路器的行为，一部分是适配器的封装问题。
> 地下那一段几乎把 `move_to_tile` 废了。

## 问题 5：`NO_PATH` 满天飞

### 现象

```json
{"status": "refused", "message": "[NO_PATH] клетка отрезана препятствиями"}
```

译文："这一格被障碍物隔开了。"

问题是 `read_map` 显示那一片是**可走草地**，`nearby_targets` 也没说不可达。
15 次 `NO_PATH` 里有 11 次发生在地下（`z=1`）。

几种具体情形：

| 情形 | 报错 |
| --- | --- |
| 地下相邻格，地形可走 | `[NO_PATH] клетка отрезана препятствиями` |
| 目标格被别的英雄站着 | `[NO_PATH] на клетку нельзя встать` |
| 守卫区内的格子 | `[NO_PATH] маршрут сквозь охрану` ＋ 附近守卫说明 |

### 绕法：一格一格 `hero:step`

冒险屏有一组**方向步进**动作：

```
hero:step:north  south  east  west  northeast  northwest  southeast  southwest
```

每次走一格，走完重新 `observe` 拿新 `revision` 再走下一格。
我在底下就是这么挪的：从 `(13,2,1)` 一路 step 到 `(9,5,1)`，三十多步，全部成功。

**代价**：一步一次 observe ≈ 1–3 秒，探完一小片地下要几分钟。但**它不骗你**。

## 问题 6：路线缓存 stale，两次调用之间状态会翻转

### 现象

```text
nearby_targets → route.state = "reachable_today"
move_to        → [STALE_REVISION] Observation is stale; observe again before acting
```

或者反过来：

```text
nearby_targets → 全部 route.state = "not_available"
                 detail = "The game's route cache is stale:
                           it was built for 2360 movement points
                           while the hero now has 1500"
nearby_targets（再调一次）→ 全部变回 reachable_today
```

**原因**：`nearby_targets` 读的是**游戏自己的路径缓存**，而缓存只在"移动力变化/过天/重新寻路"时重建。
适配器没有主动让游戏重建，只是把"缓存过期"翻译成 `not_available`。

### 实测出来的三条规律

1. **再调一次就刷新** —— 不需要额外动作，不需要 `map_click`；
2. 但**不要复用旧 `revision`** 去 `move_to`，那是 42 次 `STALE_REVISION` 的主要来源；
3. `not_available` 的目标**照样可能走得通** —— 缓存 stale 时它一律报 not_available，
   而 `move_to` 自己会重新寻路。所以"过滤掉所有 not_available"会导致**一整天原地不动**。

### 我最后采用的策略

```python
targets = nearby(rev)                  # 拿当前候选
targets = nearby(rev2) if all_not_available else targets   # 刷新一次
pick = 最近的、kind 在白名单里的、未访问过的
move_to(targetId, 新 revision)         # 失败就放弃这个目标，换下一个
```

配合"本周已访问 / 本次失败"两个黑名单，才不会在幸运泉和花园之间绕圈。
