# 03 · 对话框与按钮：语义点击时灵时不灵

> **严重度：🔴 高**。这是最消耗时间的一类 —— 不是"完全不能动"，而是"有时能动"，
> 于是每次都要试探、试错、再退回键盘。

---

## 现象 A：建造/招募确认框吃不到合成鼠标点击

第一局（Air Supremacy，72×72）里，流程是这样断的：

```text
act town:construction                → completed（打开建造列表）
act building:inspect:5               → completed（弹出确认框）
act building:buy                     → uncertain
  "Dispatch started; do not repeat using a new ID"
```

之后：**金币没扣、建筑没建**。换 `act building:cancel` 也是 `uncertain`，
`click_ui ui:8`（确认按钮）被拒：

```
[UNKNOWN_CONTROL] Use an available semantic action
```

### 绕法：键盘 Enter

```powershell
# 找到标题含 "Horn of the Abyss" 的窗口，PostMessage
PostMessage(hwnd, 0x0100, 0x0D, 0x001C0001)   # WM_KEYDOWN  VK_RETURN
PostMessage(hwnd, 0x0101, 0x0D, 0xC01C0001)   # WM_KEYUP
```

按下即成交（Mammoth Stalls、Marketplace 都是这样建成的）。

### 但是：第二局又不复现

第二局（随机图 36×36）里，同一套调用：

```text
building:inspect:11 → building:buy → completed
  "Build Castle …"    金 24,390 → 19,390，built 5 → 6
```

**同样的动作、同样的版本、只是换了一局/一张图，结果不同。**
所以这不是"动作根本不可用"，而是**在特定界面状态下，合成点击的落点或时序失效**。

我猜是：确认框的"按钮矩形"依赖某个只在特定屏幕布局下才成立的偏移；
或者 `MouseAsync` 的 `0x200 → 200ms → 0x201 → 60ms → 0x202` 节奏在 UI 淡入淡出时被打断。

## 现象 B：`scenario_info` 屏关不掉

```text
act game:scenario_info → screen = scenario_info（难度/胜利条件）
act ... 任何 close 类动作 → [UNKNOWN_CONTROL] / [WRONG_SCREEN]
click_ui ui:23 (gspexit.def) → [UNKNOWN_CONTROL] Use an available semantic action
```

该屏只暴露一个 `gspbut3.def` 的选中态和一段 "80%" 文本，**没有可用的退出语义动作**。

### 绕法：Esc

```powershell
PostMessage(hwnd, 0x0100, 0x1B, 0x00010001)   # VK_ESCAPE
PostMessage(hwnd, 0x0101, 0x1B, 0xC0010001)
```

**Esc 是万能兜底**：卡住的确认框、`exchange` 屏、`hero_screen`、`scenario_info`，
全都一发入魂。

## 现象 C：`message` 屏的两个按钮行为不一致

- `message:accept` 通常有效；
- `message:confirm` 在某些 `message` 屏直接 `[UNKNOWN_CONTROL]`（例如保存成功提示）；
- 有些 `message` 屏点金币/经验选项第一次返回 `uncertain`，第二次才成功。

所以我的 `msgloop.py` 写成了"循环点 `iokay.def`，遇 `resour82.def` 先点金币，
每轮重新 `observe` 取新 revision，最多 N 轮"。

---

## 通用判断规则（我总结的）

| 报错 | 含义 | 该做什么 |
| --- | --- | --- |
| `uncertain` + "Dispatch started" | 已经发出去了，但没验到结果 | **不要换 id 重试**，先 `observe` 复核 |
| `[UNKNOWN_CONTROL] Use an available semantic action` | 这个元素/按钮没有语义动作 | 找同屏的 `*:confirm` / `*:buy`，或直接发键盘 |
| `[WRONG_SCREEN]` | 当前屏不是你以为的屏 | `screen:close` / Esc，再 `observe` |
| `[STALE_REVISION]` | 状态变了 | 重新 `observe`，用新 revision |
